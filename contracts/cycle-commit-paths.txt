# cycle-commit-paths.txt — サイクルコミットのパス集合の**正本**（run-cycle 手順6）。
#
# 2 者がこのファイルを読む（同じ集合を 2 箇所に書かないための単一正本）:
#   1. run-cycle 手順6 の `git add -- <...>` / `git commit -- <pathspec>`（許可パス）
#   2. scripts/noop-check.rb（コミット／保留の判定。`commit_path=` として出力し直す）
#
# noop-check.rb は**ワーキングツリー全体**を見る（ここに挙げたパスだけを見るのではない）。
# 本ファイルの役割は「dirty なパスをどう分類するか」であって、監視範囲の限定ではない:
#
#   [commit]  … サイクルコミットが取り込むパス。dirty なら `reason=state-dirty`
#   [exclude] … サイクルコミットの対象外と**宣言済み**のパス。dirty でも判定に影響させない
#   どちらでもない … `reason=out-of-scope-dirty`（コミットはするが、本ファイルの見直しか
#                    人間の作業中かを人間へ知らせる。**新しいパスが黙って「変化なし」側へ
#                    落ちることが構造的に起きない**＝両者がずれたら気づける）
#
# 追加・削除したら次も同時に更新すること（テストが落ちる形で気づけるようにしてある）:
#   - scripts/tests/noop-check.test.sh   … commit_path 出力の一致（データ駆動）と分類テスト
#   - skills/adhoc/SKILL.md              … 「読み取りだけ（書かない）」の列挙。[commit] 全件が
#                                          載っていることを scripts/tests/adhoc-skill.test.sh (D)
#                                          が固定する（run-cycle が同じ周で書き換えるため）
#
# **実体が無いエントリを書いてよい**。`challenge-archive.md` は初回アーカイブまで存在せず、
# `briefs` / `.claude/skills` も使い始めるまで無い。cycle-commit.sh は git が解決できない
# エントリを pathspec から落としてコミットする（落としても入れる内容が無いため失われない）。

# reflect が「直接 diff 提案」の target と定めた資産（skills/reflect/SKILL.md 手順3 の表）。
# 置き場が [commit] にも [exclude] にも無いと、改修した周に毎回 out-of-scope-dirty が出たまま
# サイクルコミットにも入らない（Issue #174）。target の実体と置き場を 1 対 1 で対応させる:
#   recall        → CLAUDE.md（ベースライン。所在は flywheel-init の scaffold で確定済み）
#   brief         → briefs/（委譲ブリーフの雛形。例: briefs/delegation-brief.md）
#   ローカル skill → .claude/skills/（エージェントrepo 内の独自スキル）
# `.claude` 全体ではなく `.claude/skills` だけを挙げる——`.claude/settings.json` は権限定義で
# あり、サイクルコミットが自動で取り込んでよいものではない（従来どおり範囲外＝人間へ知らせる）。
