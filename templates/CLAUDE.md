## 意思決定の主体（スキルの性質 × 課題のスコープで所在が分岐する）

- 自走委譲（headless `claude -p`）には**対話相手の人間がいない**。かつ子セッションは cwd の対象 repo の設定・記憶しかロードせず、`repos.tsv`・`positions/`・横断のドメイン記憶は親だけが持ち、**人間へ問いを上げる経路も親にしかない**。**委譲するスキルごとに**次を上から評価し、最初に該当した行の所在を採る（採った所在と該当行はブリーフ冒頭に明記する）:
  1. **対話前提スキルで、§接続ツールの対話相手が `人間` と宣言されている**（該当スキルの列挙に含まれる）→ **人間**（親も代行しない）
  2. **横断（複数 repo）課題**（設計分岐・スコープ解釈・他 repo との整合に判断材料が及ぶ）→ **親が保持**
  3. **対話前提スキル**（対話相手が `親` の宣言、または宣言が無く下の判定基準で対話前提と判定）→ **親がユーザー役**（課題が単一 repo 完結でも子に決めさせない）
  4. **単一 repo 完結**かつ**対話前提でないと積極的に判定できたスキル**（例: 実装フロー）**かつ §接続ツールの「子に意思決定を委譲してよいスキル」に掲載されている** → **子が意思決定者**
  5. 上のいずれにも該当しない・判定できない・**許可リストに未掲載** → **親がユーザー役**（安全側フォールバック）
- **対話前提スキルの判定基準**: **成果物の中身（何を作るか）を意思決定者との対話で確定させる設計**のスキル＝選択肢提示と回答が品質機構そのものであるもの（要件定義・仕様策定・設計分岐の確定・受入基準・安全性のトレードオフ。例: `/define-feature`）。上流の成果物（機能仕様・受入基準）で「何を作るか」が確定済みで、どう作るかだけを担うもの（例: `/para-impl`）は対話前提ではない。**判定できないなら対話前提として扱う**。**宣言が無い・空であることを「子が決めてよい」と読まない**。**許可リストに未掲載のスキルは、対話前提でないと判定できても 5 へ送る**（列挙は人間が確定させた「子に決めさせてよい範囲」であり、判定基準で迂回できてはならない）。
- **人間が意思決定者のとき（1）**: 子へのブリーフは 3 と同じ（重大・非自明な判断は確定させず質問して終了）だが、**親も回答しない**。子が上げた問いは選択肢と推奨・判断材料を添えてサイクルレポートの次アクションへ「要対応（人間）」として上げ、その課題はステータスを前進させず保留する。**`--resume` は人間の回答を得てから**、その回答を渡して行う（親が回答を作って再開しない。ポジションが `人間` を宣言するのは、子にも親にも単独決定させないため）。
- **親が意思決定者のとき（2・3・5）**: 「停止せず決める」は渡さない。委譲先は**要件・クリティカル設計・受入基準・安全性のトレードオフ・他 repo との整合を自分で確定せず、選択肢と推奨・判断材料を添えた質問＋その時点の状態要約を最終出力にして終了**する（親が `--resume` で回答を渡し再開）。**軽微・可逆な判断（受入基準を変えない命名・書式・内部構造）のみ子が決めて仮定として記録**する。
  - **親も答えられない問いは親が代わりに決めない**: ポジション（§接続ツールの「人間へ上げる問いの種類」・§権限）の範囲を超える問い（製品方針・規制解釈・安全性のトレードオフ・スコープ変更）は、選択肢と推奨を添えてサイクルレポートの次アクションへ「要対応（人間）」として上げ、その課題はステータスを前進させず保留する。
- **子が意思決定者のとき（4）**: 委譲先は『ユーザー＝意思決定者』**役を担い、停止せず自分で意思決定まで進める**。不明点は**明示的な仮定**として成果物に書き切る。**ただし上流の成果物（機能仕様・受入基準）自体を書き換える判断へ至ったら、そこで決めず 3 に落として質問して終了**する。
- ただし**本番に影響する不可逆な操作（既定ブランチ〔`main` 等・本番反映先〕への昇格マージ / 本番デプロイ・外部公開 / 削除 / 組織外への外部送信〔通知・投稿・メール等。送信済みは撤回困難〕 / 履歴破壊）の承認ゲートはどの行でも維持**する（意思決定権の所在と不可逆操作のゲートは別物。この列挙は FR-22〔正本: `<plugin>/docs/requirements.md` §7.3〕の要約であり、判定軸は「本番への影響」と「可逆性」。列挙に無くてもこの 2 軸に当てはまる操作はゲート対象）。**作業ブランチへの push・PR（draft 含む）作成・統合ブランチ／親Issueブランチ（いずれも本番非反映）へのマージは可逆な操作**としてサイクル内で自律可。**この「集約」は FR-22 の操作承認ゲートの話に限る**——人間が承認する**操作**は既定ブランチ（`main` 等・本番反映先）への昇格＝本番反映に集約する、という意味であって、**上記の人間の意思決定（`人間` 宣言のスキル・製品方針・規制解釈・安全性のトレードオフ・スコープ変更）を不要にするものではない**。FR-22 の外にある人間判断は、操作承認とは別に必ず人間へ上げる。

## 完了報告の様式（待機・監視で終了しない）

- 自走委譲（headless `claude -p`）の子セッションは、**最終応答を確定した時点でバックグラウンドの処理・エージェントごと終了し、以後の通知は届かない**。「CI 完了を待機しています」等の中間宣言を最終出力にして終了しない。
- バックグラウンド処理・サブエージェントを起動したら、最終応答の確定前に必ず**合流（完了確認）させる**。合流できない場合は待ち続けず明示的に中断し、未完了の事実と回収手段を報告に含めて終了する。
- 自力で進められない外部待ち（CI・外部レビュー・人間承認）に達したら、待機せず**その時点の状態を報告して終了**する。
- 最終報告には**完了・外部待ちいずれの終了でも必須項目を含める**: 成果物の URL（PR・ブランチ）／コミット SHA／品質ゲート結果／置いた仮定・意思決定／未検証事項。
