# 課題台帳（Challenge Ledger）

> このエージェントが扱う課題の台帳（正本）。人間は**共有ソース**に課題を書き、このエージェントが**自分に関係する分だけ**ここへ取り込む（ingestion）。
> 記入形式は**下の記入例**のとおり（人間記入欄＋分類欄）。それだけで運用できる。
> （このファイルは claude-flywheel プラグインの雛形から生成）
>
> - **人間（共有ソース）**: 「人間記入欄」に困りごと・期待を書く（ドメインやサービスを知らなくてよい）。
> - **エージェント**: 取り込み時に「分類欄」を埋める（自分のどのポジションが引き受けるか）。

## 記入例（コピーして使う）

```markdown
### [C-001] <タイトル>

**人間記入欄**
- 起票者 / 起票日: <name> / <YYYY-MM-DD>
- 説明: <背景・困っていること・期待する状態>
- 完了条件（任意）: <こうなれば完了。複数あるときは値を空にして次行から `  - ` でネストする>
- 体感の緊急度（任意）: 高 | 中 | 低

**分類欄（エージェントが記入）**
- 担当ポジション:
- 関連サービス:
- 関連リポジトリ:
- 関連Issue:
- 関連PR:
- 優先度: P0 | P1 | P2
- ステータス: 未分類（未分類 → 分類済 → 計画承認待ち → 着手中 → 検証中 → 完了確認待ち → 完了）
- タスク案:
- 承認（人間がチェック）:
  - [ ] 計画を承認（FR-13・承認対象＝タスク案）
  - [ ] 完了を承認（FR-32）
- 取り込み元: （外部ソースから取り込んだ場合のみ ingest-challenges が付与。手書き課題は空でよい）
- 備考:
```

> **記入形式（タスク案・完了条件）**: 複数項目になるときは、フィールド行の値を空にして**直下に半角スペース 2 個でインデントした箇条書き**を書く（タスク案は番号付き `1.` `2.`、完了条件は `- `）。1 行に詰め込まない。途中に空行を入れない。
>
> ```markdown
> - タスク案:
>   1. 調査する
>   2. 実装して PR を作成する
> ```
>
> **関連リポジトリ / 関連Issue / 関連PR**: 任意・複数可（カンマ区切り）。`関連リポジトリ` は `<owner>/<repo>`、`関連Issue` / `関連PR` は `<owner>/<repo>#<番号>`（同じ owner なら `<repo>#<番号>` でもよい）。エージェントが計画時・PR 作成時に追記する。
>
> **人間の承認方法**: ステータスが `計画承認待ち` / `完了確認待ち` になったら、上の「承認」行の該当チェックボックスを `[x]` にするだけ（GitHub のモバイル / Web でタップするとその場でコミットされる）。ステータスの前進はエージェントが次サイクルで代行する。差し戻しはチェックを付けず、理由を人間記入欄か備考に書く。
>
> **`[ ] 計画を承認`（FR-13）が承認するのは「タスク案」**＝タスク分解と方向性であり、詳細な実行計画（委譲ブリーフ）ではない。詳細はエージェントが承認後に作る。判断材料は `タスク案` / `完了条件` / `関連リポジトリ` の 3 つ。粒度が粗すぎて判断できないときはチェックを付けず、理由を備考に書いて差し戻す。
