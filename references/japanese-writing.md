# 日本語出力の規約

エージェントが人間に向けて書く日本語は、**読み手が冒頭の数行で「何の話で、自分は何をすればよいか」を掴める形**にする。対象は課題台帳（説明の要約・カードの 4 項目・タスク案・備考）、サイクルレポートと journal、人間への承認依頼・質問、Issue・PR 本文、委譲ブリーフ。図・コードフェンスの書式は各スキル本文の規定に従う（この規約は文章の組み立てと語の選び方だけを扱う）。

## 組み立て

- **結論を最初の一文に置く。** 長い報告は冒頭に 3〜4 文の要約を置き、本文はその裏付けにする。「本稿では〜について述べる」のような予告から始めない。
- 見出しには節の結論を書く。「背景」「分析」だけのラベル見出しは、開いて中身を探す手間が大きい節から結論入りに直す（全見出しを同じ型に揃えない）。
- 因果と経緯は接続詞でつないだ地の文で書く。箇条書きは、項目が同じ粒度で本当に並列なときだけに使う。見出し直後に箇条書きが 3 つ以上並んだら、「そのため」「だが」でつながる関係が隠れていないか疑う。
- 太字は 1 つの文書で核になる 1 か所だけに使う。段落ごとに太字を置かない。絵文字で飾らない。
- 重要な節は実例と数値を添えて厚く書き、軽い節は一言で済ませる。全項目を同じ厚さ・同じ文型で並べない。重みづけは強弱であって順位づけではないので、並列な項目に段階や優先順位を付け足さない。
- 確信度は語尾でぼかさず、ラベルで書き分ける。ラベルは既存の確証レベルに揃える: どう確かめたか（`実コード確証` / `ドキュメント・推論由来（要検証）`）と、どれだけ確かか（`high` / `medium` / `low`）。未検証の箇所には【要確認】を付ける。「〜と思われます」を全文に散らさない。
- 書き終えたら、見出しと各段落の先頭文だけを続けて読み返す。それだけで論旨が通り、結論と次の行動まで辿り着けるかを確かめる。辿り着けなければ組み立てから直す。

## flywheel で足す規則

- カード・PR・承認依頼の冒頭には「目的」と「全体計画での位置」を置く。位置は ID ではなく言葉で書く（「新しい flywheel の 3 段目」のように）。
- 承認依頼は「推奨 → 選択肢 → 判断材料」の順に書く。推奨を最後に回さない。
- 人間向けの文書では、内輪の略語・ID（課題 ID・要件 ID・節番号・内部の呼び名）を初出で一言説明するか、名前に置き換える。ID を消す必要はない。ID だけで意味を運ばせない。
- **委譲ブリーフでは、パス・コマンド・ID を逐語のまま残す。** 子セッションはそれを手がかりに実物を探すため、言い換えると別物を指す。人間向けの文書の規則（ID を名前に置き換える）をブリーフに持ち込まない。
- コード・パス・コマンド・ID・ステータス名・ラベル名は、どの文書でも書き換えない（表記揺れを直すつもりで値を変えない）。

## 使わない言い回し

中身を増やさずに「書いている感」だけを足す型は使わない。

- 予告と総括: 「重要なのは〜」「本章では〜を扱う」「ここでは〜を見ていく」「まとめると」（直前の言い換えだけのとき）、「〜に他ならない」
- 姿勢だけの宣言: 「正面から扱う」「正面から回収する」
- 説明を伴わない強調: 「不可欠」「核心的」「鍵となる」「根本的な」「多角的」「包括的」「総合的」「非常に」「極めて」「大いに」
- 何をしたかを示さない動詞: 「掘り下げる」「深掘りする」「言語化する」「触れる」「言及する」
- 新しい情報を運ばない接続: 「〜において」「〜という側面から」「〜の観点から」、「さらに」「また」「加えて」の連打
- 根拠のない緩和: 「〜と言えるだろう」「〜かもしれない」（推量・仮定そのものを述べるときは残してよい）

## 翻訳調の比喩・擬人化の判定

英語の慣用句の直訳（「運ぶ」「開かれている」「露出する」「住む」）、無生物を主語にした擬人化（「モデルが知っている」「データが語る」）、口頭の俗語（「効く」「刺さる」「倒す」「筋がいい」）は、比喩を使ったつもりがなくても混ざる。次の 2 段で判定する。

1. その述語を初めて見た読者が、字義どおりの動作（物を運ぶ・扉が開く）を思い浮かべうるなら疑う。
2. 動作の主体と対象を具体的な語で言い直せるか試す。言い直せたら、言い直した文を書く。言い直せないなら、指す内容がまだ決まっていないので、内容を確かめてから書くか削る。
